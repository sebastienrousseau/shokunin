## 1. Strategy decisions (make these first — everything sequences off them)

### D1 — Upstream-first with exact pins (ADR-0008, write it Day 1)

A1–A4 and A6 are defects in the **same-author upstream stack**
(`staticdatagen`, `html-generator`, `mdx-gen`, `frontmatter-gen`, `rss-gen`).
You own these crates; fix them at the source, then consume with **exact
version pins** (`=x.y.z`) in ssg so the resolver can never silently mix old
and new stacks again (the comrak ×4 duplication is how A1 became
platform-divergent).

ADR-0008 must record:
- Exact-pin policy for the same-author stack, with a `cargo update` cadence.
- The regression-contract test suite in ssg (extends `docs/architecture/regression-contract.md`) that every upstream bump must pass before the pin moves.
- **Vendoring trigger:** if any upstream fix in this release takes >1 week to land or regresses twice, that crate gets vendored into `crates/` in v0.0.48. ADR-0007's content-staging shim is the canary — the goal is to *shrink* it this release (tracker #585), not grow it.
- First-party `cargo vet` audit requirement for every same-author crate at its pinned version (feeds Phase 3).

### D2 — Scope line for v0.0.47

## 2. Phase 1 — P0 correctness (spec Part A) — *"perfect"*

Every item: fix location(s) → ssg-side change → tests → acceptance. All
items land with a test in the same PR; no fix merges without one.

### 1.1 A1 — Raw HTML escaped on macOS (P0, cross-repo)

The highest-severity item: platform-divergent output that hid behind
Linux-only CI.

**Upstream (do first):**
1. `html-generator` → release 0.0.7 (or verify 0.0.6): compiles against `comrak 0.52` with `render.r#unsafe` (renamed from `unsafe_` in the 0.2x→0.5x range); unit test: `<section class="x"><p>hi</p></section>` with `allow_unsafe_html: true` renders unescaped.
2. `mdx-gen` → 0.0.2 verified against comrak 0.52 (already exists; confirm it doesn't re-pin old comrak).
3. `staticdatagen` → 0.0.11: bump both deps; in `src/compiler/service.rs::generate_html_content` (~line 193) **explicitly set `allow_unsafe_html: true`** — `HtmlConfig::default()` defaults it to `false` in 0.0.6+, which would otherwise escape raw HTML on *both* platforms (the spec's regression-risk caveat).
4. Add a macOS runner to staticdatagen's and html-generator's own CI. The root cause survived because only ssg tests on 3 OSes; the layer that renders markdown tests on one.

**ssg-side:**
- Bump to `staticdatagen = "=0.0.11"` (exact pin per D1).
- `cargo update` sweep until `Cargo.lock` holds **exactly one** comrak (0.52.x), one html-generator (0.0.7), one mdx-gen (0.0.2). This is the acceptance criterion for the dedup, not a best effort.
- New golden fixture `tests/golden/raw_html/`: page with block `<section>`, `<figure>`, inline `<svg>`, and raw HTML inside a list item. Assert emitted HTML contains `<section class=` and never `&lt;section`.
- Sanitisation stance: raw HTML pass-through is the *trusted-author* default; document in `docs/guide/` that sanitisation is an explicit opt-in pass (future `sanitize = true` config), never silent escaping.

**Acceptance:** golden test green on `ubuntu-latest` **and** `macos-latest`; A7's byte-diff job (below) covers the fixture site.

### 1.2 A2 + B1 — Feed link derivation; never hard-fail the build (P0)

**Defense in depth — fix in both layers so ssg is correct even if upstream lags:**

1. **ssg-side (unconditional):** in `src/core/content_stager.rs`, when staging a page whose front matter lacks `permalink`/`url`, inject `permalink = {site.base_url}/{relative_output_path}` into the staged front matter before `staticdatagen::compile` sees it. This single change makes A2 unreachable and implements B1 natively — the site deletes `backfill_permalink.py`. The same derivation function feeds the canonical plugin (`src/plugins/seo/canonical`) so canonical, feed `<link>`, and sitemap `<loc>` are one code path.
2. **Upstream (`staticdatagen` 0.0.11, `rss-gen` if applicable):** fallback chain `permalink → url → base_url + output_path → base_url`; a genuinely underivable entry logs a warning and skips **that entry**, never aborts the compile. Add the spec's acceptance test upstream: post with only `title` + `date` + body builds, feed link equals `{base_url}/{output_path}`.

**Tests (ssg):** `tests/core/` — stage a 3-page fixture where zero pages have `permalink`; assert build succeeds, RSS/Atom/JSON Feed links match output paths, and canonical `<link>` agrees with the feed link.

### 1.3 A3 — Structured-data "Missing title" warnings (P1)

**Upstream `html-generator`:** `generate_structured_data_from_doc` currently runs on the pre-`wrap_full_document` fragment, so `<title>` can't exist yet. Change the API to accept the title as a parameter (front-matter `seo_title` → `title` → first `<h1>` → config site title); only warn when *no* source yields one.
**ssg-side:** verify `src/plugins/seo/` derives from metadata already (it does — jsonld is metadata-driven); add a warning-free assertion to the plugins test suite: build the fixture site, capture logs, assert zero `structured_data` title warnings.

### 1.4 A4 — Shared date parsing (P1)

**New module `src/core/dates.rs`** (and mirrored util in staticdatagen):
single `parse_flexible_date(&str) -> Result<OffsetDateTime, DateParseError>`
accepting, in order: RFC 2822 (`Wed, 01 Jul 2026 07:07:07 +0000`), long form
(`July 1, 2026`), ISO 8601 (`2026-07-01`). File-mtime fallback only as last
resort, with a log line naming the field and the format that failed.

- Wire into ssg's native `news_sitemap.rs`, `rss.rs`, `atom.rs`, `json_feed.rs`, `sitemap.rs` plugins — today each parses independently.
- Upstream: staticdatagen's `generators::news_sitemap` adopts the same chain (this kills the site's `'day' component could not be parsed` spam).
- Once upstream is fixed, **shrink `NewsSitemapFixPlugin`** (`postprocess/news_sitemap.rs`) — it exists to patch upstream output; each patch it no longer needs is a deleted shim per tracker #585's direction.
- **Property test:** proptest generating dates 1990–2100, formatting into all three forms, asserting round-trip equality through `parse_flexible_date`.

### 1.5 A5 — `inLanguage` must equal `<html lang>` (P1)

**ssg-side, `src/plugins/seo/jsonld/mod.rs:115,168`:** the `"en"` fallback
is the bug's signature. Introduce one resolver used by *every* language
consumer:

```
resolve_page_lang(page) = front-matter `language` → front-matter `hreflang`
  → locale path prefix (e.g. /hi/…) → site default_language
```

Consumers: JSON-LD `inLanguage`, `og:locale`, `<html lang>` (or its
validator), hreflang self-reference. One value, four sinks — they can no
longer disagree.

**Tests:** per-locale fixture (`en`, `hi`, `fr`, plus a regioned `en-GB`);
assert all four sinks agree on every page; assert the existing
language-mismatch audit gate reports zero findings on the fixture.

### 1.6 A6 — Path-traversal false positives on code snippets (P2)

**Upstream `frontmatter-gen` → 0.0.7:** apply the traversal heuristic only
to fields that are *resolved as filesystem paths* (template names, include
paths, output targets) — never to free-text values (`description`, body).
**ssg-side:** bump pin; regression test: front matter whose `description`
contains `src/lib.rs` and `#![deny(missing_docs)]` builds warning-free,
while a template field containing `../../etc/passwd` still hard-fails
(`is_safe_path` behavior unchanged — this guard is also the Kani target in
v0.0.48, keep its contract crisp).

### 1.7 A7 — Deterministic cross-platform output (P1, new CI gate)

1. **Sweep for ordering leaks:** audit every `HashMap`/`HashSet` whose iteration reaches emitted bytes (search index JSON, taxonomy pages, sitemap entries, CSP hash lists, agentic-discovery resources). Replace with `BTreeMap` or sort-before-emit. Grep-driven checklist committed as part of the PR description.
2. **Normalize:** `\n` line endings everywhere output is written; no absolute paths (already enforced via `--remap-path-prefix` for the binary — extend the check to *site output*); no locale-dependent formatting (`to_string()` on floats/dates is the usual leak — route dates through `dates.rs`).
3. **New workflow `determinism.yml`:** build the raw-HTML fixture site + `benches/corpus/small` on `ubuntu-latest` and `macos-latest`, `tar --sort=name --mtime=@0`, compare SHA-256 across runners, fail on any difference. Also run the existing double-build reproducibility check (from `scheduled.yml`) per-PR on this fixture — cheap at fixture scale.
4. This job is **required** for merge from v0.0.47 onward. It is the regression guard the spec calls "the strongest" — it would have caught A1 the day it shipped.

### 2.3 SHA-384 SRI — make the claim true (also spec B3)

## 4. Phase 3 — Super fast (with Criterion evidence, before/after in the PR)

Baseline first: `cargo bench --bench core --bench plugins` + the 1K corpus
E2E on `main`, committed as the comparison anchor.

### 3.1 Allocation elimination (small diffs, measurable wins)

- `src/plugins/markdown_ext.rs:347`: `html.trim_end().to_string()` → `html.truncate(html.trim_end().len())` and return `html`. One full-document clone per page, gone.
- `apply_strikethrough` (`markdown_ext.rs:351`): rewrite as single-pass over the string instead of per-line `String` allocation.
- `ssg-core::parse_frontmatter` (`crates/ssg-core/src/lib.rs:137-199`): return borrowed splits — restructure so `body` is sliced once (`&input[idx..]`) and materialized once at the end; kill the `(k.clone(), v.clone())` map rebuilds by deserializing into the final map directly.
- Search extraction (`src/plugins/search.rs:76-90`): reuse a per-thread scratch `String` (rayon `map_init`) for title/heading/text extraction.

### 3.2 Skip-unchanged writes in the transform chain (biggest I/O win)

`src/plugins/plugin.rs:665-712` currently rewrites **every** HTML file even
when no plugin modified it. Change the chain to track modification
(`Cow<str>` through the chain, or a `changed: bool` compare) and skip
`fs::write` when the bytes are identical. On incremental builds and
plugin-light sites this eliminates most write traffic and — combined with
1.2 — makes the `<200ms warm rebuild` budget slack instead of tight.

API note: `Plugin::transform_html` signature change to `Cow<str>` is
breaking; acceptable pre-0.1 and caught by the new cargo-semver-checks job.
If churn is too high, ship the `changed`-tracking variant (non-breaking)
in 0.0.47 and the `Cow` contract with the collection model in 0.0.48.

### 3.3 Decouple disk writes from rayon CPU workers

Bounded `std::sync::mpsc` channel + small writer-thread pool (2–4 threads)
behind a `SiteWriter` abstraction; rayon workers `send(path, bytes)` instead
of blocking on `fs::write` (`plugin.rs:709`, `fs_ops.rs:555`,
`content_stager.rs`). ADR-0001-compatible (no tokio, no async). io_uring
backend is explicitly out of scope (v0.0.48+, Linux feature flag).

Measure: 1K and 10K corpus E2E wall time; expect the gain to concentrate at
10K on non-NVMe CI runners.

### 3.4 `i18n.rs:111` Mutex

Locale matrix is read-mostly after warm-up: replace
`Mutex<LocaleMatrixCache>` with `RwLock` (or `OnceLock` per locale if the
matrix is compute-once). Add a rayon-parallel bench hammering locale lookups
to prove the contention win — and to catch regression when B2 (i18n routing)
lands on top in 0.0.48.

### 3.5 Perf gates updated

- `tests/perf_regression.rs` budgets re-derived from post-change numbers (tighten, don't loosen).
- `BENCHMARKS.md` refreshed with new medians; `tests/docs_accuracy.rs` keeps it honest.
- Stretch: publish Criterion history to the existing GH Pages deployment (`document.yml` already deploys — add the criterion `target/criterion` HTML as a `/bench/` subpath).

**Release targets (go/no-go numbers for the CHANGELOG):**
- 1K-page cold build wall time: **−15% or better** vs 0.0.45 baseline.
- Warm incremental rebuild: **≤150ms** on the 1000-page fixture (budget was ≤200ms).
- Peak RSS on 10K corpus: **−20% or better**.
- Unchanged-file rewrites on a no-op rebuild: **0** (was: all files).
